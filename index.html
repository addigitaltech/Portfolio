Emmaculate Academy: website and school platform

One system for a school's public website, admissions, academic results, fees and administration.

Read the case study
Problem
Schools often split their website, results and fee collection across separate tools, so staff re-enter data and parents struggle to find information.
Solution
A Laravel platform with an editable public site, role-based admin, result publishing and online payments, built as the successor to our earlier Next.js school website.
Features in the code
  • Editable public website and news/events through a Filament admin
  • Roles for Super Admin, Website Admin, Content Editor, Results Admin, Finance Admin, Teacher, Student and Parent
  • Student records with IDs and CSV import, classes and academic sessions
  • Result entry, grading, positions, cumulative results, remarks and publishing
  • Student and parent result checking, PIN slips and report-card PDFs
  • Paystack and Flutterwave payment flows with receipts, and fee-based result holds
  • Promotion and graduation archive, audit logging, newsletter and email
Engineering notes
Domain-oriented Laravel code; separate public, admin, portal, API and webhook routes; policies and server-side role checks; payment verification with webhook signature and idempotency handling; automated tests on SQLite, MySQL and PostgreSQL through GitHub Actions.
Technologies
Laravel 12, PHP 8.3, Blade, Tailwind CSS, Alpine.js, Vite, MySQL/PostgreSQL, Filament, Docker

School Results Portal

A React frontend and Node API for managing results and report cards, with role-based access.

Read the case study
Problem
Schools need to record scores, compute grades and give students and parents safe access to results.
Features in the code
  • JWT login for Admin, Teacher, Student and Parent
  • Management of students, teachers, classes, subjects, sessions and terms
  • CA1 to CA3 plus exam scoring with configurable grade bands
  • Affective and psychomotor ratings, teacher and principal remarks, result publishing
  • Cumulative third-term results and printable report cards with class statistics and charts
  • Photo and logo uploads, and an optional password-reset email flow
Engineering notes
Separate frontend and API, PostgreSQL schema, ownership checks so teachers, students and parents see only their own data, hashed passwords, rate limiting and CORS configuration.
Technologies
React 18, TypeScript, Vite, Tailwind CSS, Recharts, Node.js, Express, PostgreSQL, Render
Note
Report cards print from the browser; there is no server-side PDF generator.

The exact workflow depends on the scope of each project.

  1. Discovery
    Requirements and goals.

  5. Backend and API

  7. Testing and QA
    Checks before release.
  8. Deployment
    Configuration and launch.
  9. Maintenance
    Fixes and improvements.
// standards

Security and engineering standards

Standards we apply as the project requires

Secure authentication, role-based authorization, server-side validation, safe handling of secrets, database access controls, secure API design, error handling, dependency management, backup planning and HTTPS.

Seen in our code

Role and policy checks (Emmaculate platform, Results Portal), hashed passwords (Next.js site, Results Portal), login rate limiting, payment webhook signature checks, audit logging and server-side validation in several projects. Coverage differs by project, and EduCore validation is still being tightened.
